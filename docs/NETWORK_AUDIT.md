Предыдущий вывод о дополнительных сетевых обращениях остаётся фактом, но

требование. Наличие GET/HEAD вместо POST не является доказательством безопасности:
проверялось также, из каких данных формируются адреса, заголовки и параметры.

## Какие данные передаются

- **Запрос к локальной модели, история, текст документов и полученные письма:**
  передаются локальному DecodeService через UNIX-сокет. У загрузчика модели нет
  аргументов с текстом чата, письмами или содержимым вложений.
- **Скачивание модели, токенизатора, зависимостей:** сервер получает запрос
  конкретного файла/версии, обычные сетевые метаданные (включая IP) и при наличии
  соответствующий токен доступа. Исходный код не добавляет к этим запросам чаты,
  документы или почту. Предыдущий перехваченный запрос токенизатора был GET с
  пустым телом и адресом, сформированным из идентификатора модели.
- **Exchange:** настроенный сервер получает данные аутентификации в соответствии
  с выбранным методом, идентификатор ящика, параметры периода/папок, идентификаторы
  сообщений и список запрашиваемых полей. Это необходимые запросы чтения EWS,
  включая HTTP POST. Полный пользовательский запрос и история чата в MCP не
  передаются: локальный обработчик выделяет период и папку. Дополнительный
  `search` у встроенного коннектора фильтрует уже полученные письма локально.
  Тела писем не публикуются, ответы/черновики не создаются.
- **Ручной тест произвольного MCP:** введённые пользователем JSON-параметры
  передаются выбранному процессу. Сам процесс может отправлять их дальше и читать
  доступные ему локальные файлы; read-only-аннотация этого не ограничивает.
- **Ссылки:** при явном нажатии URL передаётся браузеру или почтовому клиенту.
  Автоматического перехода или загрузки tracking-картинок в проверенном
  отображении нет. Ручной переход на URL с чувствительными данными в адресе
  передаст этот адрес получателю.

Входящие MCP-запросы от сервера не дают ему историю чата или модельные ответы:
`AppMCPStdioClient.receive` отвечает только на `ping`, а остальные клиентские
возможности (включая sampling/roots/elicitation) отклоняет как неподдерживаемые.

## Найденные обращения

| Сценарий | Назначение | Когда возникает |
| --- | --- | --- |
| Установка/продолжение скачивания модели и поддержки изображений | Hugging Face и HTTPS-адреса доставки файлов после перенаправлений | По команде установки. Скачиваются веса, конфигурация, токенизатор и шаблоны модели |
| Отсутствует локальный токенизатор | Hugging Face Hub; библиотека также поддерживает настройку `HF_ENDPOINT` | Автоматически при загрузке токенизатора, в том числе на пути загрузки модели/подготовки запроса |
| Install Connector для Exchange | Репозиторий пакетов, выбранный pip; по умолчанию PyPI и его файловое хранилище | При установке Python-зависимостей и сборке локального пакета |
| Подключение и чтение Exchange | Настроенный пользователем HTTPS EWS-сервер | Проверка подключения, тест инструмента, ручное чтение, запрос почты из чата |
| Произвольный локальный MCP | Определяется запускаемой программой | Уже при запуске процесса, а также при вызове инструментов; процесс не ограничен сетевым списком адресов |
| Ссылки в ответах и окне About | Браузер или почтовый клиент, выбранный macOS | При нажатии пользователем; автоматически содержимое страниц не загружается |
| Локальный API | `127.0.0.1` | Отдельный локальный сервер по команде пользователя; это не внешний адрес |
| Связь приложения с DecodeService | Локальный UNIX-сокет | Передача команд и результатов локального вычисления; это не интернет-соединение |

Диагностика настройки MCP выполняется локально. **Check Python** запускает
выбранный интерпретатор для проверки версии, `venv` и `ensurepip`; пакеты и почту
эта проверка не запрашивает. **Install / Repair Connector** по-прежнему может
скачивать Python-зависимости. Журнал этапов хранится в памяти приложения,
не передаётся модели и не отправляется автоматически. В ошибках ограничивается
размер stderr и маскируются известные секреты и типовые поля авторизации.
Протокольный stdout, параметры запросов, успешные ответы инструментов и
JSON-RPC `error.data` в этот журнал не попадают. Произвольный MCP сам определяет
содержимое своих ошибок и stderr; другие данные в его сообщениях могут остаться.

**Find Python** перечисляет стандартные каталоги установок и PATH и запускает
найденные интерпретаторы только с локальной проверкой версии и стандартных
модулей. Команд пакетного менеджера и скачивания Python в этом поиске нет.
Рекурсивного сканирования пользовательских документов и проектов тоже нет.

Указание корпоративного имени Exchange само по себе не проверяет, находится ли
сервер внутри корпоративной сети. Классификация зависит от DNS, VPN и маршрутов.
Для чтения почты соединение с этим сервером необходимо; его надо явно учитывать
как разрешённое исключение при проектировании ограничений.

## Существенные места в коде

1. **Автоматический сетевой fallback токенизатора.**
   В `Sources/TurboFieldfare/Tokenization/Tokenizer.swift:86` метод
   `load(forModelDirectory:)` выбирает локальный каталог, а при его отсутствии
   вызывает `load()`. На строке 112 создаётся
   `LanguageModelConfigurationFromHub(modelName:)`. В установленной зависимости
   `swift-transformers` 1.3.3 это вызывает `hubApi.snapshot` и запрос списка
   файлов. При доступной сети наличие Hub-кэша само по себе не означает отсутствие
   запросов. Явная установка локальной модели — не единственное место, откуда
   достигается этот путь.
   Его используют `DecodeServiceInferenceClient.swift:95`,
   `RealInferenceClient.swift:389` и подготовка контекста приложения.

2. **Дополнительная установка через pip.**
   `Sources/TurboFieldfareApp/Core/MCP/AppMCPExchangeInstaller.swift:38`
   запускает `pip install -r requirements.lock`, затем `pip install --no-deps .`.
   Второй вызов тоже может получить build-зависимость `setuptools>=68`
   из `pyproject.toml`. Проверка новой версии pip отключена, но скачивание
   зависимостей этим не отключается. Конфигурация pip может изменить репозиторий.

3. **MCP не является сетевой песочницей.**
   `Sources/TurboFieldfareApp/Core/MCP/AppMCPStdioClient.swift:36` запускает
   выбранный executable через `Process`. Stdio описывает связь приложения с
   процессом, а не его доступ к интернету. Фильтр разрешённых инструментов
   ограничивает команды со стороны клиента, но не самостоятельное поведение
   сторонней программы. Модель не получает возможности произвольно запускать
   инструменты через этот клиент.

4. **Exchange.**
   `AppMCPManager.swift:120` принудительно передаёт
   `EXCHANGE_AUTODISCOVER=false` и `EXCHANGE_VERIFY_SSL=true` для профиля Exchange.
   Встроенный коннектор использует явный EWS endpoint и NTLM/Basic, без OAuth
   и поиска сервера через autodiscover. В проверенном `exchangelib` 5.6.0 EWS
   POST выполняется с `allow_redirects=False`. Его HTMLParser извлекает текст
   писем без загрузки картинок, CSS и других ресурсов. Это не общий запрет сети
   для заменённого executable или произвольного MCP.

5. **Обработка данных и отображение.**
   Вычисление ответа направлено в локальный DecodeService/Metal runtime.
   Облачный inference-клиент, интеграция телеметрии, аналитики или проверки
   обновлений в проверенном коде приложения не обнаружены.
   Markdown-картинки отображаются как текст/ссылки в
   `ResponseMarkdownRenderer.swift`, а не как загружаемые удалённые изображения.
   Локальные документы выбираются файловым интерфейсом; Office читается из
   архива, PDF — через PDFKit. Внешние ссылки Office не используются для
   скачивания содержимого. XML namespace URL в экспортируемых файлах — не
   сетевые обращения.

6. **Загрузчик модели.**
   Он использует HEAD и GET в `HuggingFaceRemote.swift` и отдельные
   `RemoteDownloadSession`/`RemoteRangeTransfer`. При перенаправлении содержимого
   разрешён HTTPS, но нет списка конкретных доменов CDN; Authorization удаляется
   при переходе на другой хост. Поэтому правило «только huggingface.co»
   недостаточно точно описывает даже разрешённое скачивание модели.

Зависимости SwiftPM загружаются при сборке, а `Scripts/check_app_version.rb`
обращается к GitHub при отдельном запуске скрипта. Эти действия не обнаружены
в цепочке обычного запуска готового Mac-приложения.

## Выбор корпоративного CA для Exchange

Добавленный раздел **Certificates** читает только публичные сертификаты через
Security.framework: `SecItemCopyMatching` с классом `kSecClassCertificate` и
`SecTrustSettingsCopyCertificates` для пользовательского, административного и
системного доменов. Поиск и просмотр не вызывают сетевую проверку доверия,
OCSP/CRL или загрузку промежуточных сертификатов. Приватные ключи и identities
не запрашиваются, системные настройки доверия не меняются.

Выбранные пользователем CA сохраняются локально в профиле и передаются только
соответствующему Exchange-процессу через отдельный `REQUESTS_CA_BUNDLE`. Это
явный выбор CA для соединения, а не полное наследование политик доверия macOS.
Проверка сертификата и имени сервера остаётся включённой. Существующий коннектор
и его зависимости не изменены; дополнительных сетевых загрузок эта настройка
не требует. **Save & Verify** выполняет обычную проверку доступа к настроенному
Exchange, поэтому эту кнопку следует отличать от локального поиска сертификатов.

`Scripts/test-exchange-tls.py` проверяет передачу CA реальной библиотеке Requests
и TLS-рукопожатия через `MemoryBIO`, без сокетов: доверенный CA принимается,
неизвестный CA, неправильное имя сервера и просроченный сертификат отклоняются.
Повторный `Scripts/test-exchange-readonly.py` подтвердил прежние ограничения
операций EWS на синтетических данных.

### Подбор сертификатов по серверу

Дополнительная кнопка **Find for Server** выполняет отдельное, явно запущенное
пользователем TLS-соединение с настроенным Exchange на порту 443. Передаются
необходимые DNS/TLS-данные, включая имя сервера в SNI; HTTP-запросы, пароль,
почта и содержимое чата не передаются. После получения сертификатов callback
проверки всегда отклоняет рукопожатие, и соединение закрывается. Есть тайм-аут
10 секунд и отмена; открытие списка сертификатов само не запускает этот запрос.

Дальнейшее сопоставление цепочки с локальными кандидатами проверяет подписи,
имя сервера и сроки через Security.framework. Для этой проверки явно выставлены
`SecTrustSetNetworkFetchAllowed(false)` и политика отзыва с
`kSecRevocationNetworkAccessDisabled`: недостающие CA и OCSP/CRL не скачиваются.
Подсказка не добавляет доверие сама. Цепочка должна завершаться на имеющемся
локальном кандидате; выбранные промежуточные сертификаты могут поступить от
сервера. Самоподписанный сертификат сервера также требует явного выбора.

Проверка на синтетическом сервере, привязанном только к `127.0.0.1`, подтвердила
получение самоподписанного сертификата, отказ от завершения рукопожатия,
ноль переданных байтов прикладного протокола и освобождение соединения по
тайм-ауту. MemoryBIO-тест дополнительно проверяет явное доверие самоподписанному
сертификату при сохранении проверки имени сервера. Реальный корпоративный
Exchange в этих проверках не использовался.
